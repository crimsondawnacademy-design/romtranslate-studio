## TL;DR
App desktop open source (Tauri 2 + React + Rust) pra tradução de ROMs com IA, local-first, patch-first. Spec em `docs/SPEC.md`. Repo PÚBLICO; **v0.1.1 publicada em 21/09** (a v0.1.0 tem o bug do NDS — use a 0.1.1) com binários das 4 plataformas (CI de release por tag). 11 formatos detectáveis, 9 com ciclo completo (extrair→traduzir→validar→reinserir→patch): RTSF, GBA, NDS, NES, SNES, GameCube, PS1 (incl. BIN raw com EDC/ECC e multi-track .cue), PS2 (incl. DVD >2 GiB em streaming), PSP; Wii/Wii U só detecção. **Relocação de ponteiros em GBA, NDS e PS1** (21/09): tradução maior que o original vai pra outro lugar com a tabela reapontada — só pra strings referenciadas por TABELA (spec proíbe busca global). GBA: fim do ROM. NDS: o arquivo cresce e a FAT é reapontada. PS1: sobra do setor final do arquivo (<2 KB). ARM9/EXE/PS2/PSP ficam de fora de propósito (ver DECISIONS). Tabelas em arquivo: u32 (run 3) e u16 (run 4), sempre em ordem crescente. 134 testes (125 rust + 9 vitest). Limites que ainda travam uso real: sem descompressão, sem Shift-JIS/edição de fonte, nada testado em ROM real.

- [2026-09-21] claude/opus-5 — RELOCAÇÃO NO NDS E NO PS1 + BUG ANTIGO DO NDS CORRIGIDO. ⚠️ CORREÇÃO: eu tinha escrito aqui que "NDS ARM9 e PS1 EXE cabem no mesmo motor mudando a base" — ERRADO. A detecção funcionaria, mas o ARM9 e o EXE são COPIADOS pra RAM com tamanho declarado e logo depois vêm BSS (zerada no boot) e heap: texto anexado some ou é sobrescrito. O GBA só é seguro porque o cartucho é lido direto pela CPU. Então a relocação foi pra dentro dos ARQUIVOS de dados: `pointers::file_relative_tables` (offset relativo ao arquivo, run mínimo 3 — número pequeno aparece à toa em dado binário; conta no DECISIONS). NDS: o arquivo com string realocada ganha cópia no fim do ROM (alinhada 0x200, padding 0xFF), a FAT (todas as entradas-alias) passa a apontar pra ela, header 0x080 (total usado) e 0x014 (capacidade 128KB<<n) atualizados, CRC do header recalculado — formato conferido no GBATEK antes de codar. PS1: sobra do último setor do arquivo (o hardware lê setor inteiro, então a sobra sempre chega na RAM), recusa se a sobra não estiver zerada (dado escondido), tamanho atualizado no directory record nos DOIS endians (`IsoFile.record_offset` novo), EDC/ECC regenerado pelo loop de sempre; teto por string = sobra − alinhamento − terminador vira `max_bytes` (validador erra acima dele, avisa abaixo; editor pinta de vermelho só acima). PS2/PSP ficam in-place: leem bytes, a sobra não chega garantida. Refatorado: `ensure_pointers_untouched`, `mark_relocatable`, `is_terminated`, `to_file_relative` no módulo de ponteiros; GBA usa os mesmos. BUG PRÉ-EXISTENTE (desde o Sprint 8) achado pelo teste de fluxo: o NDS varre ASCII e UTF-16LE, texto ASCII lido como UTF-16 vira "CJK" falso no MESMO offset com o MESMO id (`scan-<offset>`) — no banco as duas leituras se fundiam e "NOVO JOGO" era gravado como N\0O\0V\0... por cima do ASCII (corrupção silenciosa; a UI ainda mostrava o texto falso). Corrigido na raiz com `resolve_encoding_overlaps` (uma leitura por trecho: ASCII se cobre ≥3/4 do run UTF-16 e não tem cara de kana — byte alto 0x30 em metade das unidades) + guarda geral no `plan_in_place`: duas traduções nunca gravam nos mesmos bytes. Projetos de NDS antigos: re-extrair. Também: mensagem "formato não reconhecido (GBA, NES, SNES)" da UI estava parada em 3 plataformas — tirei a lista. Verificado no preview do app: 4 casos do contador (sem teto / dentro / estourando teto / fixa), console limpo. +9 testes.

## Glossário do projeto
- **provider**: implementação de `TranslationProvider` (async); Ollama local ou endpoint OpenAI-compatible; modelo NUNCA hardcoded
- **TM**: translation memory por projeto; chave = texto normalizado (trim+collapse, case preservado) + par de idiomas
- **glossário**: termos por projeto injetados no prompt SÓ quando aparecem no batch; `no_translate` = manter original
- **allow_remote_translation**: guarda de privacidade — endpoint fora de localhost exige opt-in explícito
- **scanner (Camada A)**: descoberta genérica em `scan.rs`; NÃO garante reinserção segura (Camada B, Sprint 5)
- **.rtsproj**: diretório do usuário (project.json + translations.sqlite + subdirs); NUNCA contém cópia da ROM
- **synth**: fixtures sintéticas — proibido byte de jogo real no repo
